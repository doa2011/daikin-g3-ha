# G3 屏幕媒体中心：第六页电子相册

## 目标与显示模型

电子相册固定使用 G3 组合布局第六页（API 页码从 1 开始）。每张照片先把正常布局切换到第六页，再通过上游媒体接口显示；照片结束后，底层正常布局仍停留在第六页。播放不会重写或覆盖用户的 SCN3 页面布局。

重要硬件边界：RC6 的 SCN3 页面组件类型目前是时钟、数值、文字、图表、天气和提醒，没有原生 JPEG 图片组件。因此当前实现使用 `screen.push.send` 的定时图片媒体视图覆盖显示，页面六作为相册常驻基础页；它不是把 JPEG 写进 SCN3 布局。若要求照片成为第六页内持久化的原生组件，需要另行扩展 ESP32/屏幕 MCU 固件协议与 LVGL 渲染，不能仅靠 HA 集成实现。

第六页必须预先在 G3 WebUI 的“设置 → 屏幕”布局中创建并启用。集成只调用 `screen.page.set {page:6}`，不会自动创建页面或更改用户布局。页面不存在或禁用时，服务明确失败，不会继续上传照片。

## 照片来源与处理

- 从 Home Assistant 可访问的本地目录扫描 JPG/JPEG/PNG/WebP；群晖 NAS 可挂载到 HA 可访问目录。
- 支持顺序或随机播放；随机模式每轮重新洗牌。
- Pillow 处理 EXIF 方向、透明背景与纵横比，默认 `cover` 裁切，输出 480×854 竖屏 RGB baseline JPEG。
- JPEG 上传预算 128 KiB；超过预算时逐级降低质量，仍无法满足则报错。
- 图片按 512 字节分块上传；每一步等待 MCU 对应 request/session ACK，最后校验 ready、长度和 CRC32。

## 启动与停止

```yaml
action: daikin_g3.start_album
data:
  entry_id: "G3配置条目ID"
  directory: /media/photos
  shuffle: true
  seconds: 30
  brightness: 30
  wake: true
```

停止：

```yaml
action: daikin_g3.stop_album
data:
  entry_id: "G3配置条目ID"
```

每台 G3 一个后台相册任务。重复启动会被拒绝；摄像头截图、文字通知和仪表盘等前台任务会协作式停止相册，避免并发争用媒体 MCU。停止在当前照片进入终态后生效。

## 实机验证

1. 在 WebUI 布局编辑器确认第六页存在且已启用。
2. 先执行单张图片流程，确认屏幕实际显示、方向、裁切、颜色和亮度。
3. 使用至少三张照片启动随机轮播，确认每张照片显示时底层页面是第六页。
4. 手动翻页离开第六页，等待下一张照片，确认相册会重新切回第六页。
5. 调用 `stop_album`，确认当前照片结束后停止。
6. 轮播期间触发 `show_camera` 或 `show_message`，确认相册让位。
7. 测试 NAS 挂载、权限、空目录、损坏图片、超大图片、断网及 MCU busy。

## 连续播放实验路径

当设备声明 `screen.push.update` 等必要能力时，HA 相册实体采用同一通知 ID 原位换图；下一张 JPEG 在上一张显示期间上传，最大 64 KiB。正常停止才主动关闭当前通知，上传失败不主动清除旧图。该路径仍为通知视图，尚非原生全屏；旧固件沿用定时通知路径。

## 原生第六页（实验）

新 ESP32 与 MCU 同时支持时，HA 自动选用 `screen.album.set/clear`，图片仅在页六全屏呈现。需启用第六页，手工进入即可，轮播不会抢占其他页。保留原有设备休眠/背光规则；目前相册专用亮度和唤醒参数不覆盖原生页。旧端继续采用通知方案。
