# G3 屏幕媒体中心：第六页电子相册

## 显示方式与版本协商

HA 在启动轮播时读取设备能力，并同时检查 ESP32 的 screen.album.set/clear、媒体上传动作，以及 MCU 媒体状态协议版本。只有两端均声明原生相册能力时，才使用原生路径；旧 ESP32/MCU 继续使用兼容的连续媒体通知路径。

原生路径不使用 screen.push.send 通知框。MCU 将已上传并解码的 480×854 JPEG 作为独立 LVGL 图层覆盖在组合布局第六页，照片铺满屏幕。它不是 SCN3 页面布局中的 JPEG 组件，也不会修改用户保存的 SCN3 布局。

第六页必须预先在 G3 WebUI“设置 → 屏幕”中创建并启用。启动原生相册时，HA 先保存当前页，再确认切换到第六页，随后才发送原生相册显示命令。停止时，如果用户仍停留在第六页，HA 恢复启动前的页面；如果用户手动切换到了其他页面，则尊重用户选择，不会强行切回。第六页不存在或禁用时明确失败，不上传照片。

## 照片处理与传输

- 从 Home Assistant 可访问的本地目录扫描 JPG/JPEG/PNG/WebP；群晖 NAS 可挂载到 HA 可访问目录。
- 支持顺序或随机播放；随机模式每轮重新洗牌。
- Pillow 处理 EXIF 方向、透明背景与纵横比，默认 cover 裁切，输出 480×854 竖屏 RGB baseline JPEG。
- 相册实验路径单张 JPEG 上限 64 KiB；超出预算时由图像处理阶段逐级降低质量，仍无法满足则报错。
- 图片按 512 字节分块上传；每一步等待 MCU 对应 request/session ACK，最后校验 ready、长度和 CRC32。
- 预上传下一张时保留当前照片；只有新图解码并被 MCU 接受后才释放旧图。解码失败不主动清除旧图。

## 启动与停止

```yaml
action: daikin_g3.start_album
data:
  entry_id: "G3配置条目ID"
  directory: /media/photos
  shuffle: true
  seconds: 30
  brightness: 30
  wake: true
```

停止：

```yaml
action: daikin_g3.stop_album
data:
  entry_id: "G3配置条目ID"
```

每台 G3 一个后台相册任务。重复启动会被拒绝。原生相册不修改设备全局亮度、唤醒和休眠策略；当前版本的 brightness、wake 参数只对兼容通知路径生效。

普通通知或摄像头媒体可以暂时显示在前景；原生相册不会清除它们，也不会强制抢占。前景媒体结束后，MCU 可重新显示已保留的相册图层。若前景媒体持续占用，下一张图片最多等待 30 秒，超时会报告暂停/失败，不会清空当前相册图像。

用户手动离开第六页时，下一次换图会停止相册；清理只移除本会话拥有的图像，并保留用户手动选择的页面。协议或解码失败时，HA 尝试清理当前会话；若清理 ACK 丢失，会保留资源所有权信息以便显式停止重试。

## 实机验证清单

1. 在 WebUI 布局编辑器确认第六页存在且已启用。
2. 记录当前页面（例如第 1 页），启动相册，确认 HA 自动切换到第 6 页。
3. 确认照片铺满 480×854 屏幕，不出现通知卡片、边框或缩小的布局区域。
4. 轮播至少三张照片，确认上一张在下一张解码成功前持续显示。
5. 停止相册，确认恢复启动前的页面；另测播放中手动切页，确认停止后保留手动选择。
6. 测试通知、摄像头、休眠/唤醒、亮度策略、断网、损坏图片、超大图片和 MCU busy。
7. 确认传感器、UART、OTA、配置备份恢复和原有屏幕页面仍正常。

CI 与宿主测试不等于实机 LCD 扫描确认。当前 MCU ACK 表示图像解码/相册 ID 已接受，不代表物理 LCD 已完成扫描显示。
