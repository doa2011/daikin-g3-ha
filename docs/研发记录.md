# 中文研发记录

## 2026-11-25：G3 第六页电子相册

- 基于上游 BRY88BBA15G RC6 文档，确认屏幕为 480×854、最多 8 个组合页面；远程换页使用 1 起始页码，指定第六页为 `screen.page.set {page:6}`。
- SCN3 已公开组件类型没有 JPEG 图片组件；上游媒体接口的 `screen.media.begin/chunk/commit` 上传 JPEG，`screen.push.send` 以定时媒体视图显示图片。当前实现采用“第六页作为底层常驻页面 + 定时媒体图片视图”，不修改用户 SCN3 布局。
- 增加切页确认：必须先确认第六页存在且启用，随后才处理图片上传；页面无效时不消耗媒体上传。
- 保留既有 EXIF 旋转、480×854 裁切、baseline JPEG、128 KiB 限额、512 字节分块、CRC/ACK、随机轮播及协作停止机制。
- 新增测试：切到第六页先于上传、页六禁用时拒绝且不上传、目录不存在。
- 实机尚待验证：实际 MCU JPEG 解码、屏幕显示、颜色裁切和连续轮播。

## 2026-11-26：连续相册第一轮

- 支持 screen.push.update 的设备采用同一通知 ID，旧图显示期间预传新图；到播放时间且上传成功后原位替换，确认 displayed 后释放旧图。旧固件保留原路径。
- 相册专用 JPEG 预算 64 KiB，先观察真实耗时；不修改通用媒体协议。停止时仅清理本会话。异常后保留旧图，显式停止可清理；固件最长一小时自动退出保护。
- 本轮仍为通知视图，不声称原生全屏。后续需独立页六原生显示、固件端解码失败保护、传输吞吐和传感器回归。
